# hotaru overlay

蛍（hotaru）のように、押したキーが暗がりにぽっと灯る。

VIA 対応キーボードのキーマップを画面に半透明で出す常駐アプリ。**いまのレイヤー**と
**押しているキー**が見える。[Tauri v2](https://v2.tauri.app/)。Windows / macOS。

キーボードの情報はアプリに1つも入っていない。使う人が次の2つのファイルを登録する。

| | ファイル | どこで手に入るか |
|---|---|---|
| 配置 | VIA の定義ファイル（`.json`。`vendorId` / `productId` / `matrix` / `layouts.keymap`） | usevia.app の Design タブに読み込ませるもの。キーボードの作者が配っている |
| キーマップ | VIA の Save で保存した `.layout.json` | usevia.app の Configure → SAVE + LOAD → Save |

## 初めて起動したとき

何も登録されていないので、配置ファイルを選ぶダイアログが開き、続けてキーマップを
選ぶダイアログが開く。キャンセルしたときは、オーバーレイに何を登録すればよいかが
出る。登録はトレイのメニューからいつでもやり直せる。

登録したパスは設定ファイルに残り、次からはそのファイルで起動する。どちらのファイルも
1秒ごとに更新を確かめるので、VIA で割り当てを変えて同じ `.layout.json` に Save
すれば、1秒以内に表示が変わる。

キーマップの `vendorProductId` が配置ファイルの `vendorId` / `productId` と
違うとき（別のキーボードのキーマップ）は、読まずにそう表示する。

### 配置ファイルで読むもの

KLE（Keyboard Layout Editor）の書式どおりに読む。幅と高さ（`w` / `h`）、回転（`r` / `rx` / `ry`）、
デカール（`d`）に対応している。VIA の約束ごとは次のとおり。

- 左上の凡例 `"row,col"` … そのキーのマトリクスのセル
- 凡例の 9 番目（右下）`"group,choice"` … レイアウトの選択肢。**choice 0 だけを描く**
- 凡例の 10 番目（中央）`"e"` … エンコーダ。左上が `"番号,向き"`（0 が反時計回り、1 が時計回り）
- 凡例の 10 番目が `"eN"` … エンコーダ N の両方向を1つのキーで描く（左半分が反時計回り、右半分が時計回り）

## 押したキーとレイヤーを知る仕組み

キーボードに聞く。ファームが VIA の raw HID でコマンド **0xA3** に「有効なレイヤー」と
「押されているマトリクスのセル」を答えると、このアプリはそれを 1 秒に 250 回聞く
（`src-tauri/src/hid.rs`）。VIA の他の機能には触らないので、VIA とは同時に使える。

ファーム側のコードは [`firmware/overlay.c`](firmware/overlay.c)。キーボードの `.c` に
貼ってビルドする。返事が 32 バイトなので、**マトリクスは 10 行 × 16 列まで**、
エンコーダは 0 番だけが光る。

0xA3 に答えないファームでも、配置とキーマップは出る（レイヤー 0 のまま、押しても
光らない）。オーバーレイには「ファームが 0xA3 に答えない」と出る。

ファームは問い合わせの間に押されたセルも覚えておくので、短いタップも1コマは光る。

## ビルドと起動

```sh
npm install
npm run tauri dev        # 開発
npm run tauri build      # 配布用（Windows なら msi / exe、macOS なら .app / .dmg）
```

macOS 用は macOS の上で、Windows 用は Windows の上でビルドする（Tauri はクロスビルドしない）。
macOS では初回にキーボードへのアクセス（入力監視）を許可するよう聞かれることがある。

## 確かめる

```sh
cd src-tauri
cargo test                                   # KLE の読み・キーマップの形・0xA3 の返事の解読
cargo run --bin probe -- <VIA の定義 .json>   # 窓なしでキーボードの返事を印字する
```

`probe` はキーを押すとそのセルが `#` になり、MO(1) を押すと `layers` の
ビット1が立ち、エンコーダ 0 を回すと `knob` が 1（反時計回り）か 2（時計回り）になる。
アプリの前にファームを疑うときはこれで。

## 操作（トレイ / メニューバー）

| | |
|---|---|
| 表示 | ON / OFF |
| 透明度 | 30〜100% |
| 位置 | 左上・上・右上・左・中央・右・左下・下・右下（画面を 3×3 に分けた9か所。端は作業領域から 16px 空ける） |
| レイヤー | 自動（キーボードから）/ Layer n 固定（キーボードなしで確かめる用） |
| 配置ファイルを選ぶ… | VIA の定義ファイルを登録する（キーマップが未登録なら続けて聞く） |
| キーマップを選ぶ… | VIA の `.layout.json` を登録する |
| ファイルを読み直す | 2つのファイルをすぐ読む |
| ログイン時に起動 | |

窓は常に最前面・クリック透過・フォーカスを取らない。

## 凡例

VIA が保存するキーコード（`KC_A`、`MO(1)`、`LSFT(KC_9)` など）を短い凡例にする
（`src/keycodes.ts`）。Shift 付きの記号は US 配列の読み方で出す。
